# Запасной путь через omblepy

Обычно всё делается в браузере и эти скрипты не нужны. Они пригодятся в одном случае:
**сопряжение из браузера не проходит**.

## Почему такое возможно

При записи ключа прибор инициирует BLE-сопряжение на уровне операционной системы
(SMP Security Request). Web Bluetooth этим процессом не управляет — им занимается сама ОС,
и повлиять на него из страницы нельзя. На macOS это обычно проходит незаметно, но
гарантий нет.

Выгрузка истории таким ограничением не страдает: там нужен только обмен по уже открытому
соединению, и она работает в браузере в любом случае — при условии, что прибор уже сопряжён.

## Что делать

Сопрячь прибор один раз из терминала:

```bash
./tools/omblepy.sh pair
```

Ключ, который записывает omblepy, **совпадает с ключом веб-приложения по умолчанию**
(`deadbeaf12341234deadbeaf12341234`). Поэтому после этой одной команды браузер начинает
работать с прибором самостоятельно — возвращайтесь на вкладку «Синхронизация» и жмите
«Подключить и выгрузить».

## Выгрузка данных прямо из терминала

Если хочется обойтись без браузера совсем:

```bash
./tools/omblepy.sh read
```

Файлы появятся в `tools/out/`. Любой из них (`user1.csv`, `user2.csv`, `ubpm.json`)
приложение принимает: **Настройки → Данные → «Импорт из файла»**. Совпадающие измерения
не задваиваются.

## Если не находит прибор

- Снимите тонометр из системного списка Bluetooth и попробуйте снова.
- Bluetooth на приборе гаснет примерно через минуту — включайте его непосредственно перед запуском.
- На macOS Терминалу нужно разрешение на Bluetooth: Системные настройки → Конфиденциальность
  и безопасность → Bluetooth.

Первый запуск скачивает [omblepy](https://github.com/userx14/omblepy) в `tools/omblepy`
и создаёт виртуальное окружение в `tools/.venv`. Обе папки в `.gitignore`.
