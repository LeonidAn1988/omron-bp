## Копия дневника — как устроено

Три файла, и порядок между ними важен.

| Файл | Что делает |
|---|---|
| `android/.../BackupFile.java` | SAF: `choose` / `write` / `read` / `check` / `forget`. Разрешение долгоживущее, система держит его как `persisted=0x3` |
| `src/logic/crypto.ts` | Конверт PBKDF2-SHA256 210 000 + AES-GCM-256. Неверный пароль отличается от испорченного файла — это не мелочь, иначе человека гоняют по кругу |
| `src/logic/backup.ts:shouldWriteBackup` | Когда переписывать файл. Чистая функция, под тестами |

**Чего нельзя ломать при следующих правках:**

- **Замок файла — не то же самое, что число записей.** Смена пароля или
  включение шифрования старит файл сама по себе. Без этого экран обещал
  зашифрованную копию, пока в файле лежал открытый дневник.
- **Пароль применяется целиком, а не по букве.** Экран держит черновик у себя и
  отдаёт его по уходу из поля. Иначе первая же нажатая клавиша уходила в файл
  как ключ шифрования, копия отмечалась сохранённой, и настоящий пароль в файл
  уже не попадал.
- **Неудача записи бывает двух видов.** `write` возвращает `retry` (папка
  недоступна, доступ цел) и `lost` (файл удалён, доступ отозван). Сводить их
  обратно к `false` нельзя: тогда выключенный Wi-Fi отвязывает облачную папку, и
  человек ищет файл заново после каждой поездки в метро.
- **Пустой дневник поверх копии не пишем.** Записать пустоту — потерять копию.
- **Конверт готовится в одном месте** (`envelope()` в `src/ui/useBackup.ts`) для
  всех трёх путей: автокопии, «сохранить в файл», «поделиться». Разойдясь, они
  один раз уже дали открытый дневник в облако при включённом шифровании.

**Пароль лежит в localStorage** (`omron.backup-password`), и это осознанно: он
защищает файл **в облаке**, а не телефон — дневник рядом лежит открытым. Держать
его только в памяти означало бы, что после каждого перезапуска копии молча
перестают идти.

## Что проверено на устройстве 1 сентября

Mate X3, Android 15, вся цепочка целиком:

- выбор файла в «Загрузках» — SAF-окно предлагает и Облако@Mail.ru, и локальные
  папки; файл записан сразу после выбора, 14 037 байт;
- шифрование: пароль набран по буквам — в файл не ушёл ни один промежуточный
  вариант; применён по уходу из поля — файл перезаписан конвертом, 18 892 байта;
- смена пароля при неизменном числе записей перезаписала файл (соль другая);
- восстановление зашифрованной копии — 49 записей, настройки на месте;
- неверный пароль → «Не подошёл пароль», не «файл повреждён»;
- `check()` на чужой URI → `ok:false`, на свой → `ok:true` с именем;
- удалённый файл провайдер «Загрузок» создаёт заново при записи — сценарий
  `lost` там не воспроизводится, он проверен через `check()` напрямую;
- вывод ключа из пароля — 43–62 мс.

**Не проверено:** перезагрузка телефона с выбранным файлом (система пишет
`persisted=0x3`, то есть разрешение сохранено на диск, но самой перезагрузки не
делали) и `pm clear` — это стёрло бы настоящий дневник владельца.

## Грабли — чтобы не наступить снова

- **Gradle виснет** на сетевой проверке зависимостей. `./gradlew --stop`, потом
  сборка с `--offline` — секунды вместо минут.
- **`adb shell` съедает стандартный ввод** — каждому вызову в скриптах нужен
  `</dev/null`, иначе до python доходит пустая строка.
- **Кириллические имена переменных в bash не подставляются** — `$ОТВЕТ` пуст, и
  проверка «срабатывает» вхолостую.
- **`am force-stop` снимает будильники приложения** — для проверки уведомлений
  нужен `am kill`.
- **Установку перекрывают два окна EMUI** — «Внимание» с «Продолжить» и проверка
  AppGallery с «Установить». Без них `adb install` висит до таймаута.
- **React слушает `focusout`, а не `blur`** — в проверках через CDP отправлять
  надо `new FocusEvent('focusout', { bubbles: true })`, иначе `onBlur` не
  срабатывает и правка выглядит сломанной, хотя работает.
- **`Reveal` прячет содержимое визуально** — свёрнутый блок остаётся в
  `innerText`. Судить о состоянии по тексту нельзя, надо смотреть `data-open`.
